## 2026-10-12 · Как пришла к идее

Первый проект — ReleaseScribe (релиз-посты из GitLab + Telegram). Проблема настоящая, но упёрлась в данные: корпоративный GitLab, выгрузка только на почту / через API с подбором параметров, рабочие данные нельзя отправлять во внешнюю LLM. Вывод: **для учебного стартапа данные должны быть у пользователя на руках и без ограничений.**

Книги подходят идеально: файл у читателя есть всегда, RAG — не фича, а суть продукта.

### Проблема
- После перерыва не помню, что было и кто есть кто.
- В длинных книгах путаюсь в персонажах и их именах.
- Через месяц после прочтения сюжет почти стирается.

Почему существующее не работает: пересказы — на всю книгу со спойлерами и только для известных книг; ChatGPT выдумывает или спойлерит; заметки на полях никто не ведёт.

### Сценарий: «всё вместе»
Вернуться после перерыва (пересказ, персонажи, вопрос) + запомнить надолго (вопросы по главе + повторение ошибок).

## v0.1 — решения

| Решение | Почему |
|---|---|
| FB2 + EPUB | Мои форматы; FB2 — стандарт русскоязычных библиотек |
| FB2: кодировка из XML-декларации, поддержка .fb2.zip | Старые FB2 в windows-1251, многие библиотеки отдают zip |
| FB2: главы = листовые секции, заголовки родителей склеиваются | Иначе в «Войне и мире» 15 разных «Глава I» |
| EPUB: глава = файл из spine; короче 300 символов — пропуск | Обложки и оглавления — не главы |
| **Фрагменты не пересекают границу главы** | Основа защиты от спойлеров: у фрагмента ровно одна глава |
| **Фильтр `chapter < upTo` в поиске** | Спойлер невозможен архитектурно, а не «запрещён в промпте» |
| **Разбор главы (digest) — 1 раз на главу, кэш, только прочитанные** | Пересказ и персонажи строятся из разборов: дёшево и без доступа к будущему |
| Разбор — дешёвая модель (`DIGEST_MODEL`) | Глав много, задача простая |
| Склейка персонажей — код, не LLM | Детерминированно и бесплатно; правила: совпало имя/обращение или фамилия |
| Ошибки в тестах — в `progress.json` на сервере | Это и есть «повторение»; браузерное хранилище для такого ненадёжно |
| Клиент запрашивает разбор по главам сам | Дешёвый способ показать прогресс «читаю главу 3 из 8» без SSE |
| Демо — «Капитанская дочка» (Викитека, 1960) | Общественное достояние, 14 глав, ~190 тыс. символов |

## Что узнала

1. **Фильтр поиска не защищает от знаний модели.** На «Кто такой Пугачёв?» после 3 глав поиск честно находит только сцену с вожатым в метели (имя ещё не названо). Но модель *знает* роман и может сказать «вожатый — это Пугачёв». → Общее правило `NO_SPOILERS` во всех промптах: не использовать своё знание книги, не называть героя, если он ещё не назван. _Проверить на реальной модели — главный тест v0.2._
2. **Лексика важна для имён.** e5-small плохо различает имена собственные; добавила вес совпадения основ слов 0.4 (опыт ReleaseScribe).
3. **Викитека ограничивает частоту запросов** при скачивании глав — нужна пауза и User-Agent.

## Баги
- **«Эта глава ещё не прочитана» при смене главы.** Гонка: вкладки пересоздавались сразу при смене `upTo` и запрашивали разбор новых глав раньше, чем сервер сохранил закладку (а сервер разбирает только главы до сохранённой). → Переключаем `upTo` в UI только после успешного `PUT /progress`. Вывод: если защита на сервере опирается на сохранённое состояние, клиент обязан сначала его сохранить.

## Edge cases
- Вопрос про ещё не прочитанное → «в прочитанных главах об этом не сказано».
- Вопрос не о книге → вежливый отказ.
- Огромная глава (> 40 тыс. символов) → разбор по частям, склейка.
- Тест по непрочитанной главе / разбор непрочитанной → 400.
- Закладку откатили назад → ошибки из «будущих» глав не показываются в повторении.
- Файл не FB2/EPUB, EPUB без container.xml, книга без глав → понятные ошибки.

## 2026-10-12 · v0.2 — дневник чтения

Идея пользователя: «было бы классно сделать дневник чтения». Чтобы это была ИИ-функция, а не блокнот:

| Решение | Почему |
|---|---|
| Запись создаётся **сама при сдвиге закладки вперёд**; одна запись на день, расширяется | Вести дневник «вручную» никто не будет — сессия чтения и есть повод для записи |
| ИИ пишет «что произошло» за сессию + 2 вопроса для размышления | Рефлексия запоминается лучше пересказа; вопросы — про мотивы героев, не проверка фактов |
| Мысли, ответы и цитаты читателя **участвуют в поиске** («что я думала про Швабрина?») и в пересказе | Дневник становится частью RAG: <fragment> — текст книги, <note> — мысли читателя |
| Цитата ищется в тексте → «гл. 4»; дословно нет — абзац с ≥80% слов → «≈ гл. 1» | Цитаты запоминают неточно: «Береги честь смолоду» у Пушкина — «береги платье снову, а честь смолоду» |
| Отзыв собирается **только из записей читателя**; нет мыслей — 400 «не из чего собрать» | ИИ не должен придумывать мнение за человека |
| Записи про главы дальше закладки (закладку откатили) — скрыты от ИИ | Иначе собственные записи читателя стали бы источником спойлеров |
| Локальная дата для «сегодня» | В UTC вечернее чтение уезжает на завтра и рвёт серию |
| Серия дней не теряется, пока сегодня ещё не читали | Иначе утром каждый день «серия 0» |

### Реальный EPUB — служебные разделы
Тест на настоящем EPUB («Монолог фармацевта», том 5) и прогон пользователя на другой книге показали: «Аннотация», «Имена персонажей», «Профили персонажей», «Иллюстрации» считались главами. Модель на разборе аннотации честно ответила: «В переданном тексте нет главы книги: это аннотация…».
→ `books/extra.ts`: служебные разделы по заголовку. Не пересказываются, не попадают в тесты, но **остаются в поиске** (список имён полезен для «кто это?»). Закладка по умолчанию — после служебных разделов в начале. Определение на лету — работает и для уже загруженных книг.

Открытый вопрос: это том 5 серии — читатель знает тома 1–4, а ИИ нет. Возможная v0.3: «предыдущие тома прочитаны» → подгрузить их в библиотеку как контекст.

### Mock загрязнял кэш
Mock-разборы глав сохранялись в `.cache` — при включении реальной LLM подтянулись бы заглушки. → mock ничего не сохраняет; `CACHE_DIR` для тестов.

## 2026-10-12 · v0.3 — серии, удаление, визуал

### Предыдущие тома серии
| Решение | Почему |
|---|---|
| Серия из метаданных: FB2 `<sequence>`, EPUB `calibre:series` / `belongs-to-collection`; запасной вариант — «Том 5» в названии | Пользователь не должен вручную связывать тома, если файл это уже знает |
| Подсказка «в библиотеке есть тома 1–4 — учитывать?» + ручной выбор + загрузка тома прямо из панели | Автоопределение не всегда сработает |
| Подключённый том = прочитан целиком (закладка в конец, **без** записи в дневник) | Это не сегодняшнее чтение; разбор глав разрешён только для прочитанных |
| Поиск: текущий том до закладки + прошлые тома целиком; id фрагментов с префиксом книги | Иначе `c3.12` из разных томов совпадут |
| «Напомнить прошлые тома» — разбор глав тома + краткое содержание, по кнопке и один раз | Это десятки запросов: только явно и с прогрессом |
| Пересказ текущего тома получает краткие содержания прошлых как контекст | Связность: «Маомао снова…» |
| Персонажи прошлых томов — из уже готовых разборов, с подписью тома | Не запускаем дорогой разбор неявно |

### Удаление книги
Удаляется папка книги (текст, разборы, дневник, прогресс), индекс в памяти и ссылки из других томов. Подтверждение в UI — дневник не восстановить.

### Визуал (запрос пользователя: тёмная тема, голубые оттенки, адаптив, анимации)
- Тёмная тема с голубым/бирюзовым градиентом, стеклянные панели.
- Десктоп ≥1200 — 3 колонки; планшет — 2, цитаты — шторка снизу с кнопкой «❝ Цитаты»; мобильный ≤767 — 1 колонка, вкладки листаются вбок с затуханием у края.
- Анимации: смена вкладок, появление карточек и списков, «мерцающие» заглушки вместо «Загрузка…», переливающийся прогресс; `prefers-reduced-motion` отключает.
- Проверено скриншотами headless Chrome. Урок: headless не делает окно уже ~500px и обрезает скриншот — «мобильный» надо снимать во `<iframe width=390>`, иначе кажется, что вёрстка вылезает за экран.
- `background-clip: text` перекрашивает и эмодзи в градиент — эмодзи вынесены из градиентного текста.
- Открытая книга и вкладка — в адресе (`#book=…&tab=…`): обновление страницы не выкидывает в библиотеку.

### 402 от OpenRouter (снова)
«You requested up to 1500 tokens, but can only afford 1193» — закончился лимит ключа. Код не поможет; варианты: пополнить / поднять лимит ключа, или бесплатная модель для разбора глав (`DIGEST_MODEL=google/gemma-4-31b-it:free`, с лимитами по частоте).

### Переключатель на Anthropic API
Пользователь хочет «свой аккаунт Claude». Подписка claude.ai не оплачивает API — нужен ключ из console.anthropic.com (отдельный баланс). Сделала `LLM_PROVIDER=anthropic`:
| Решение | Почему |
|---|---|
| Отдельные модули `ai/anthropic.ts` и `ai/openrouter.ts`, `llm.ts` — только выбор | Два SDK не смешиваются в одном файле; остальной код не знает, кто провайдер |
| `claude-opus-5-5` — ответы/пересказ, `claude-haiku-5-5` — разбор глав | Как и раньше: сильная модель там, где важно качество, дешёвая — на массовом разборе |
| Без `temperature` | У Opus 5.5 / Haiku 5.5 параметры сэмплинга убраны — запрос с ними даёт 400 |
| `max_tokens` 16000 (а не 1500, как для OpenRouter) | Мышление у этих моделей всегда включено и тратит тот же лимит — маленький лимит обрезал бы JSON |
| `effort: medium` явно | У Opus 5.5 значение по умолчанию — medium; задаём явно, чтобы было видно и настраивалось |
| Серверный `fallbacks: "default"` для основной модели | Роман может содержать насилие — если классификатор отклонит фрагмент, Anthropic сам повторит на другой модели. У Haiku 5.5 серверного fallback нет |
| `stop_reason: refusal` / `max_tokens` → понятные ошибки; ошибки SDK по классам → «неверный ключ», «нет средств», «нет связи (VPN?)» | Пользователь видит, что делать, а не «500» |
Проверено: с неверным ключом приходит 401 «неверный ANTHROPIC_API_KEY» — api.anthropic.com из сети доступен.

## 2026-10-13 · Первый прогон тест-кейсов

Подробно — `TEST_CASES.md` → «Прогон 1». Модель — бесплатная Nemotron (на ключе OpenRouter нет кредитов).

- **Спойлеры: 6 из 6 ✅.** «Кто такой Пугачёв?» на гл. 3 → «не сказано»; вожатый не назван; дуэль гл. 4 не раскрыта; в пересказе и персонажах нет Пугачёва. Даже слабая модель держит — значит, работает архитектура (фильтр поиска + разборы только прочитанных глав), а не «честность» модели.
- **Исправлено по итогам:**
  - ответ без валидных цитат показывался как «не найдено» → теперь «⚠️ ИИ не привёл цитату»; несуществующие id логируются;
  - «думающие» модели съедают `max_tokens` на рассуждения → JSON обрывается: понятная ошибка по `finish_reason: length`, лимит проверки ответа 400 → 700;
  - ошибки OpenRouter (401/402/403/404/429) — понятным текстом, как у Anthropic;
  - загрузка не-книги давала 500 → 400.
- **Не исправлено (качество модели):** латиница в именах, фактические ошибки в разборе («Зурин проиграл»), «коротко» не соблюдается, «погода» → ответ про буран вместо отказа. Ожидание: на Claude этого не будет — проверить.
- **Вывод про бесплатные модели:** 50 запросов в день на весь OpenRouter-аккаунт — хватает на ~15 кейсов; для полного прогона нужен платный ключ.

## 2026-10-13 · Автотест интерфейса (mock)

Ключа с балансом нет — включила `LLM_MODE=mock` и прогнала всё, что не зависит от текста модели: 33 проверки API и 19 сценариев интерфейса в настоящем Chrome (puppeteer, вне проекта). Все прошли.

Что узнала:
- Тест «тап по фону закрывает шторку» сначала падал: тап шёл в центр фона, а его закрывает сама шторка (80% экрана). Ошибка теста, не продукта — но добавила закрытие по Esc.
- Единственная ошибка консоли — 404 на `favicon.ico` → иконка 🔖 через data-URI.
- Ожидание «сеть затихла» зависало из-за Google Fonts → в тесте жду элементы, а в продукте шрифты подключены неблокирующе (`media=print` + `onload`): при медленном доступе к Google страница показывается сразу системным шрифтом.
- Ключ Anthropic у пользователя оказался ID ключа (36 символов, не `sk-ant-…`) → в статус ИИ добавлена проверка формата с подсказкой; `tsx watch` теперь следит и за `.env`.

## 2026-10-13 · Сверка с заданием перед публикацией

| Требование | Где |
|---|---|
| Конкретная проблема, не чат-бот | Помнить сюжет без спойлеров — README «Проблема» |
| RAG по данным пользователя | Его книги (FB2/EPUB) + его дневник; фрагменты, эмбеддинги, гибридный поиск, источники |
| ИИ — ключевая функция | Генерирует (пересказ, вопросы, отзыв), извлекает (персонажи), анализирует (проверка ответа) |
| Показывать, что ИИ думает | Прогресс «Читаю главу 3 из 8», мерцающие заглушки |
| Источники и обоснование | Цитаты к ответам, метки «гл. N» у пересказа, «где это в тексте» в тестах |
| Позволять исправлять | Мысли и ответы в дневнике; **пересказ сессии — «Исправить» / «Переписать»** (добавлено при сверке); закладку можно откатить |
| Когда ИИ не знает | «В прочитанных главах об этом не сказано», «⚠️ ИИ не привёл цитату», отказ вне темы |
| Edge cases | Нет данных / вне scope / галлюцинации (проверка id цитат и номеров глав) / огромные главы (разбор по частям) / служебные разделы |
| DEV_NOTES, промпт-журнал | `DEV_NOTES.md`, `PROMPTS.md` (с результатами прогонов) |
| README: проблема, для кого, зачем ИИ, технологии, архитектура, запуск, как попробовать | `README.md` |
| Деплой (плюс) | Не сделан: локальная модель эмбеддингов (~120 МБ) и ключ LLM на сервере — следующий шаг |
