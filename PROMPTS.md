# Промпт-журнал

Все промпты — `server/src/ai/prompts.ts`.

## Общее: NO_SPOILERS (v1, 2026-10-12)
Добавляется во все промпты. Причина: модели знают известные книги, фильтр поиска не мешает им «вспомнить» финал.
Ключевая формулировка: «Если герой ещё не назван по имени — не называй его».
Результат (прогон 1, бесплатная Nemotron): **сработало 6 из 6** — «Кто такой Пугачёв?» на гл. 3 → «В прочитанных главах об этом не сказано»; вожатый описан только по гл. 2 и не назван; дуэль гл. 4 не раскрыта; в пересказе и персонажах Пугачёва нет. Вывод: главная защита — архитектура (поиск и разборы только по прочитанным главам), промпт — второй рубеж. На Claude ещё не проверено.

## DIGEST — разбор главы (v1)
- summary 4–7 предложений «кто что сделал, почему, чем кончилось» — без литературоведения.
- characters: name = самое полное имя *как в тексте*; без имени — описание («вожатый»). Это важно для спойлеров и склейки.
- Модель — `DIGEST_MODEL` (дешёвая).

Результат: структура JSON соблюдается. ❌ Слабая модель путает факты («Зурин проиграл» вместо «Гринёв проиграл») и смешивает латиницу («Petr»). Промптом это не лечится — нужна модель сильнее (Haiku/Sonnet). ❌ Первая версия разбирала «Аннотацию» как главу — модель честно ответила «это не глава». Исправлено кодом (служебные разделы), а не промптом.

## RECAP — пересказ (v1)
- Два режима: short / full; акцент на последних главах.
- У абзаца — номера глав; код отбрасывает номера > upTo.
- openThreads — «что держать в голове», без догадок о развязке.

Результат: метки глав верные, спойлеров нет. ❌ Режим short игнорируется — пересказ всё равно длинный. Гипотеза на v0.4: дать лимит в словах («не больше 80 слов») вместо «1–2 абзаца».

## ASK — вопрос (v1)
- Фрагменты с id и номером главы; ответ только по ним.
- Два «отказных» исхода: нет в прочитанном / не про книгу.
- Код: found = true только если есть хотя бы одна валидная цитата.

Результат: «нет в тексте» работает («любимый цвет» → «не сказано»). ❌ Модель отвечала по сути верно, но без id цитат → код прятал ответ как «не найдено». Исправлено: ответ показывается с пометкой «⚠️ ИИ не привёл цитату». ⚠️ «Какая завтра погода?» → ответ про буран в книге вместо отказа: формально по книге, оставила.

## QUIZ / GRADE (v1)
- 4 вопроса «что важно помнить для дальнейшего чтения», не мелкие детали.
- Проверка по смыслу, три уровня; «не помню» = wrong → в повторение.

Результат: QUIZ — 4 вопроса по сюжету с цитатами ✅. GRADE — верный ответ своими словами → correct ✅. ❌ У «думающей» модели лимит 400 токенов ушёл на рассуждения, JSON оборвался → лимит 700 и понятная ошибка по `finish_reason: length`.

## DIARY_ENTRY — запись сессии (v1)
- Вход: разборы сегодняшних глав + одна строка на каждую раннюю главу (контекст).
- summary 2–4 предложения «живо, как в дневнике, но без оценок за читателя».
- questions — про мотивы и выбор героев, «как бы вы поступили», не проверка фактов и не про будущее.

## REVIEW — отзыв (v1)
- Мнения — только из записей читателя; от первого лица; промежуточный — так и сказать.
- Мало записей → короткий отзыв + что дописать (`enough: false`).

## ASK v2 — с дневником
- `<fragment>` — книга, `<note>` — мысли читателя; «не путай: факты — из fragment, мнения — из note».
